# ممیزی سازگاری افزونه‌های پیامک و پرداخت — Bamero

**تاریخ بررسی:** ۱۴ نوامبر ۲۰۲۶  
**هدف محیط:** WordPress 7.1.4، PHP 8.5، WooCommerce 11.2.2

## ۱. پیامک و OTP: WSMS + MeliPayamak

| جزء | نسخه/وضعیت فعلی | نتیجه |
|---|---|---|
| WSMS | 7.2.12، آخرین انتشار ۶ نوامبر ۲۰۲۶ | نسخه جاری WordPress.org؛ tested up to WordPress 7.1.4 |
| MeliPayamak gateway | در فهرست gatewayهای WSMS رایگان | برای transport پیامک کاندید مناسب |
| SMS OTP login / 2FA | در All-in-One طبق صفحه رسمی افزونه | نیازمند مجوز پولی؛ پیش از خرید SKU نهایی شود |
| All-in-One یک‌سایته | ۵۹ دلار/سال طبق صفحه رسمی قیمت | پیشنهاد فعلی برای staging، نه خرید خودکار |

**تصمیم پیشنهادی:** از WSMS برای transport پیامک و جریان OTP آماده استفاده شود، نه اینکه OTP موازی و تکراری در Bamero Core ساخته شود. MeliPayamak در WSMS free gateway فهرست شده، اما ورود پیامکی/ثبت‌نام OTP و 2FA در WordPress.org به All-in-One نسبت داده شده است. <https://wordpress.org/plugins/wp-sms/> <https://wsms.io/pricing/> <https://wsms.io/gateways/melipayamak/>

**مواردی که هنوز باید در staging ثابت شوند:**
- ورود پیامکی از صفحه My Account ووکامرس و redirect صحیح بعد از ورود؛
- ثبت‌نام شماره جدید و جلوگیری از ایجاد حساب تکراری برای فرمت‌های مختلف موبایل؛
- ثبت/تکمیل نام و نام خانوادگی؛ صفحه رسمی فعلی WSMS تضمین نمی‌کند که فرم ثبت‌نام OTP دقیقاً فیلدهای موردنیاز بامرو را جمع‌آوری کند؛ در صورت نیاز، این بخش با Bamero Core تکمیل می‌شود؛
- انقضا، replay، سقف تلاش، rate limit، cooldown و عدم افشای وجود حساب؛
- جداسازی ورود مشتری از ورود مدیر/کارکنان؛
- تحویل واقعی SMS در اپراتورهای هدف، اعتبار پنل و Sender ID مجاز.

**مجوز:** هنوز خرید یا نصب All-in-One تأیید نشده است. صفحات رسمی فروشنده دربارهٔ نام/قیمت بسته‌ها تفاوت‌هایی دارند؛ صفحهٔ قیمت فعلی برای All-in-One تک‌سایته ۵۹ دلار/سال اعلام می‌کند. قبل از پرداخت باید SKU، تعداد دامنه و فعال بودن SMS Login/OTP روی همان SKU از checkout فروشنده تأیید شود.

## ۲. درگاه پرداخت: افزونه رسمی Zibal

- آخرین نسخهٔ فهرست‌شده: **2.1**.
- changelog: سخت‌سازی callback و verify، نگهداری چند trackId برای سفارش و اصلاح مبلغ/ارز/موبایل.
- صفحهٔ WordPress.org سازگاری نحوی PHP تا 8.5 را ذکر می‌کند، اما مقدار Tested up to آن WordPress 6.9.11 است؛ محیط هدف بامرو WordPress 7.1.4 است.
- بنابراین نسخه 2.1 منسوخ اعلام نمی‌شود، اما سازگاری آن با WordPress 7.1.4 و WooCommerce 11.2.2 **اثبات نشده** و در حال حاضر برای production تأیید نیست.

**گیت پذیرش staging:** پرداخت موفق، ناموفق، لغو، timeout، callback تکراری، trackId تکراری، مبلغ/ارز نامنطبق، replay و تکمیل idempotent سفارش. تا عبور از همهٔ موارد، کلید پذیرنده در محیط واقعی تنظیم نمی‌شود.

منبع رسمی: <https://wordpress.org/plugins/zibal-payment-gateway-for-woocommerce/>

## ۳. API مستقیم ملی پیامک — ملاحظات امنیتی

مستند رسمی MeliPayamak متد SendOtp را با پارامترهای username/password/from/to/code مستند کرده است. نمونهٔ PHP همان صفحه SSL host/peer verification را خاموش می‌کند؛ این الگو ناامن است و در Bamero کپی نخواهد شد. هر پیاده‌سازی مستقیم باید با TLS verification فعال، احراز هویت فعلی تأییدشده و API رسمی جاری انجام شود. فعلاً مسیر ترجیحی، Adapter افزونهٔ WSMS است.

منبع رسمی: <https://www.melipayamak.com/api/sendotp/>

## ۴. وضعیت اجرایی

- هیچ‌یک از این افزونه‌ها در WordPress واقعی نصب یا فعال نشده‌اند.
- هیچ کلید API، رمز پنل، شماره فرستنده یا پذیرنده در Git ذخیره نشده است.
- تا دریافت مجوز/تأیید خرید و دسترسی staging، کدنویسی جریان کامل OTP و پرداخت نباید با فرض سازگاری انجام شود.
- این سند ممیزی نسخه و تصمیم پیشنهادی است؛ تأیید نهایی فقط پس از تست staging انجام می‌شود.
