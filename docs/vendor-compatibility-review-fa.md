# ممیزی سازگاری افزونه‌های پیامک و پرداخت — Bamero

**تاریخ بررسی:** ۱۴ نوامبر ۲۰۲۶  
**هدف محیط:** WordPress 7.1.4، PHP 8.5، WooCommerce 11.2.2

## ۱. پیامک: ماژول اختصاصی Bamero Core + ملی‌پیامک

- ارائه‌دهندهٔ منتخب: **ملی‌پیامک**.
- پیاده‌سازی transport در افزونهٔ Bamero Core انجام می‌شود؛ WSMS و افزونه‌های پیامکی ثالث در پروژه استفاده نمی‌شوند.
- Adapter مبتنی بر REST API، با TLS verification فعال، timeout محدود و عدم retry خودکار ساخته شده است.
- نام کاربری پنل، API key وب‌سرویس و شمارهٔ خط مجاز از متغیرهای محیطی خوانده می‌شوند؛ رمز عادی پنل نباید جایگزین API key شود.
- صفحهٔ وضعیت پیامک در پیشخوان، صرفاً پیکربندی را بررسی می‌کند و secret را نمایش یا ذخیره نمی‌کند.
- ارسال واقعی، اعتبار API key، sender و IP allowlist هنوز در staging تأیید نشده‌اند.

منابع فنی:
- https://www.melipayamak.com/api/
- https://docs.rs/melipayamak/latest/melipayamak/

## ۲. درگاه پرداخت: افزونه رسمی Zibal

- آخرین نسخهٔ فهرست‌شده: **2.1**.
- changelog: سخت‌سازی callback و verify، نگهداری چند trackId برای سفارش و اصلاح مبلغ/ارز/موبایل.
- صفحهٔ WordPress.org سازگاری نحوی PHP تا 8.5 را ذکر می‌کند، اما مقدار Tested up to آن WordPress 6.9.11 است؛ محیط هدف بامرو WordPress 7.1.4 است.
- بنابراین نسخه 2.1 منسوخ اعلام نمی‌شود، اما سازگاری آن با WordPress 7.1.4 و WooCommerce 11.2.2 **اثبات نشده** و در حال حاضر برای production تأیید نیست.

**گیت پذیرش staging:** پرداخت موفق، ناموفق، لغو، timeout، callback تکراری، trackId تکراری، مبلغ/ارز نامنطبق، replay و تکمیل idempotent سفارش. تا عبور از همهٔ موارد، کلید پذیرنده در محیط واقعی تنظیم نمی‌شود.

منبع رسمی: <https://wordpress.org/plugins/zibal-payment-gateway-for-woocommerce/>

## ۳. API مستقیم ملی پیامک — ملاحظات امنیتی

نمونهٔ قدیمی SendOtp که SSL host/peer verification را خاموش می‌کند ناامن است و در Bamero استفاده نمی‌شود. پیاده‌سازی فعلی از REST API با TLS verification فعال استفاده می‌کند؛ OTP در فاز بعد و پس از بررسی API رسمی الگوهای خدماتی و تأیید حساب staging ساخته می‌شود.

منبع رسمی: <https://www.melipayamak.com/api/sendotp/>

## ۴. وضعیت اجرایی

- هیچ‌یک از این افزونه‌ها در WordPress واقعی نصب یا فعال نشده‌اند.
- هیچ کلید API، رمز پنل، شماره فرستنده یا پذیرنده در Git ذخیره نشده است.
- تا دریافت دسترسی staging و تأیید API key و sender ملی‌پیامک، ارسال واقعی و جریان OTP نباید با فرض سازگاری انجام شود.
- این سند ممیزی نسخه و تصمیم پیشنهادی است؛ تأیید نهایی فقط پس از تست staging انجام می‌شود.


## ۵. تصمیم نهایی مالک — حذف WSMS و پیاده‌سازی مستقیم در Bamero Core

این تصمیم جایگزین تمام پیشنهادها و بررسی‌های قبلی WSMS در همین سند است:

- WSMS در پروژهٔ بامرو نصب، فعال یا استفاده نخواهد شد. هیچ خرید یا تمدید آن نیز انجام نمی‌شود.
- ارسال پیامک فقط از طریق ماژول اختصاصی Bamero Core و REST API ملی‌پیامک انجام می‌شود.
- قرارداد `SmsProvider` و Adapter اختصاصی `MeliPayamakRestProvider` پیاده‌سازی شده‌اند؛ تنظیمات اتصال از environment دریافت می‌شود و صفحهٔ مدیریتی وضعیت اتصال را بدون افشای secret نشان می‌دهد.
- آزمون‌های قراردادی برای TLS verification، HTTPS endpoint، شمارهٔ معتبر، پاسخ موفق/خطای provider، timeout/network error و عدم ارسال با ورودی نامعتبر به CI افزوده شده‌اند.
- API key وب‌سرویس ملی‌پیامک لازم است؛ رمز عادی ورود به پنل نباید جایگزین آن شود. اگر محدودیت IP در پنل فعال است، IP خروجی سرور باید در allowlist ملی‌پیامک ثبت شود.
- هنوز ارسال واقعی در staging انجام نشده است؛ شناسهٔ خط فرستنده، اعتبار پنل، دسترسی IP و قالب/نوع پیام باید با حساب واقعی تأیید شوند.
- این پیاده‌سازی به معنی تکمیل OTP نیست؛ جریان OTP، ذخیرهٔ hash، انقضا، مصرف اتمیک، rate limit، cooldown، anti-enumeration و اتصال به My Account در فاز بعد توسعه می‌یابد.

منابع:
- https://www.melipayamak.com/api/
- https://docs.rs/melipayamak/latest/melipayamak/
