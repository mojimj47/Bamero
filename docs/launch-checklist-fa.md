# چک‌لیست راه‌اندازی فروشگاه Bamero

این چک‌لیست بین آماده‌بودن کد قالب و آماده‌بودن کسب‌وکار برای دریافت سفارش واقعی تفاوت می‌گذارد. تکمیل قالب به‌تنهایی به معنی آماده‌بودن پرداخت یا مجازبودن فروش نیست.

## ۱. میزبانی و محیط‌ها

- [ ] میزبان با نیازمندی‌های رسمی WooCommerce 10.8+ تطبیق دارد: WordPress 6.9+، PHP 8.3+ (طبق راهنمای فعلی تا PHP 8.4 آزموده‌شده)، MySQL 8.0+ یا MariaDB 10.6+، HTTPS و حداقل 256MB حافظهٔ WordPress؛ برای فروشگاه فارسی، افزونهٔ PHP `mbstring` فعال است. در بررسی ۱۲ نوامبر ۲۰۲۶، آخرین WordPress پایدار 7.1.4 و تگ پایدار اعلام‌شدهٔ WooCommerce 10.8.1 بود؛ پیش از انتشار، نسخه‌های روز و مستندات میزبان دوباره بررسی شوند.
- [ ] فضای کافی، امکان تهیهٔ نسخهٔ پشتیبان و آزمون بازیابی آن در محیط staging تأیید شده است.
- [ ] محیط staging جدا از production ساخته شده و تغییرات ابتدا آن‌جا بررسی می‌شوند.
- [ ] DNS دامنه به میزبانی درست اشاره می‌کند؛ گواهی TLS معتبر نصب است و HTTP به HTTPS هدایت می‌شود.
- [ ] فایل `.env` و تنظیمات محرمانه خارج از GitHub نگهداری شده‌اند؛ مقادیر local نمونه در سرور استفاده نشده‌اند.
- [ ] حساب مدیر یکتا و امن با گذرواژهٔ قوی و احراز هویت چندمرحله‌ای ساخته شده است؛ دسترسی ویرایش فایل از پیشخوان در production غیرفعال است.
- [ ] نسخهٔ پشتیبان زمان‌بندی‌شده از دیتابیس و فایل‌ها گرفته می‌شود و بازیابی آن در محیط staging تمرین شده است.

## ۲. نصب و هویت فروشگاه

- [ ] WordPress و افزونهٔ رسمی WooCommerce نصب و به‌روز هستند؛ نسخه‌های افزونه‌ها با PHP و قالب سازگارند.
- [ ] قالب Bamero فعال است؛ زبان سایت، منطقهٔ زمانی، نشانی فروشگاه، پیوندهای یکتا و HTTPS تنظیم شده‌اند.
- [ ] نام/لوگو، ایمیل پشتیبانی، نشانی تماس و اطلاعات حقوقی کسب‌وکار جای متن‌های عمومی قالب را گرفته‌اند.
- [ ] صفحات فروشگاه، سبد خرید، تسویه‌حساب، حساب کاربری و سیاست حریم خصوصی به صفحات درست متصل شده‌اند.
- [ ] اطلاعات واقعی کالا، موجودی، قیمت، مالیات و تصاویر مجاز ثبت شده‌اند؛ محصول آزمایشی یا placeholder برای خریدار نمایش داده نمی‌شود.

## ۳. پرداخت، ارسال و ایمیل

- [ ] ارز، واحدها، مالیات و قواعد قیمت‌گذاری بر اساس کشور/منطقهٔ فروش و نظر متخصص محلی پیکربندی شده‌اند.
- [ ] مناطق ارسال، روش‌ها، هزینه‌ها، محدودیت‌های کالا و زمان‌بندی تحویل مطابق عملیات واقعی تنظیم شده‌اند.
- [ ] درگاه پرداخت معتبر برای بازار هدف نصب و با کلیدهای واقعی در secret store یا پنل امن ارائه‌دهنده تنظیم شده است؛ هیچ کلیدی در مخزن نیست.
- [ ] سفارش موفق، پرداخت ناموفق، لغو، بازپرداخت، سفارش مهمان، کد تخفیف، موجودی تمام‌شده و خطای ارسال با sandbox یا روش تست ارائه‌دهنده آزمایش شده‌اند.
- [ ] ایمیل تأیید سفارش، تغییر وضعیت و بازپرداخت با SPF/DKIM/DMARC و سرویس ارسال مناسب بررسی شده؛ پیام‌ها به مقصد واقعی تحویل می‌شوند.
- [ ] برای هر سناریوی پرداخت، رکورد سفارش در WooCommerce به وضعیت درست می‌رسد و رویداد تکراری باعث برداشت یا سفارش تکراری نمی‌شود.

## ۴. آزمون فروشگاه و دسترس‌پذیری

- [ ] چیدمان روی گوشی، تبلت و دسکتاپ و جهت RTL در مرورگرهای اصلی بررسی شده است.
- [ ] منو با صفحه‌کلید و لمس کار می‌کند؛ فوکوس قابل‌دیدن است؛ عنوان و متن جایگزین تصاویر محصول درست‌اند.
- [ ] جست‌وجو، دسته‌بندی، مرتب‌سازی، صفحهٔ محصول، گالری، تعداد کالا، سبد، کوپن و تسویه‌حساب عملاً آزموده شده‌اند.
- [ ] عنوان‌های صفحه در خانه، برگه، نوشته، فروشگاه، محصول، دسته، جست‌وجو، صفحه‌بندی و 404 بررسی شده‌اند؛ عنوان خالی/تکراری یا خلاف محتوای واقعی باقی نمانده است.
- [ ] H1 و سلسله‌مراتب headingها در صفحهٔ نوشته‌ها، صفحات اصلی و HTML واقعی فروشگاه/محصول مرور شده‌اند؛ عنوان‌ها به محتوای همان صفحه می‌پردازند.
- [ ] برای هر صفحهٔ مهم توضیح متای مرتبط و یکتا در همان سامانهٔ تأییدشدهٔ SEO تنظیم شده است؛ HTML نهایی تگ تکراری یا توضیح ساختگی ندارد.
- [ ] دقیقاً یک breadcrumb دیداریِ درست برای صفحات مرتبط وجود دارد؛ مسیر دستهٔ محصول، ترتیب والد تا صفحهٔ جاری و خروجی JSON-LD با افزونه/قالب دیگر تعارض ندارد.
- [ ] پیوندهای داخلی منو، دسته‌ها، محصولات و footer به مقصدهای واقعی می‌رسند؛ پیوند شکسته، URL نمونه یا anchor خالی باقی نمانده است.
- [ ] canonicalهای HTML/HTTP با دامنهٔ مرجع و URLهای واقعی تطبیق دارند؛ staging به دامنهٔ production canonical نمی‌شود.
- [ ] پاسخ واقعی `/robots.txt` با WordPress، افزونهٔ SEO، وب‌سرور/CDN و sitemap تطبیق داده شده؛ robots به‌عنوان کنترل امنیت یا جایگزین noindex استفاده نشده است.
- [ ] sitemap واقعی از endpoint هسته یا افزونهٔ انتخاب‌شده دریافت می‌شود؛ فقط یک index مرجع نگه داشته شده و URLهای آن عمومی، معتبر و بدون تکرارند.
- [ ] staging با احراز هویت یا دسترسی محدود از عموم پنهان است؛ تنظیم noindex آن بررسی شده و robots.txt مانع crawl لازم برای مشاهدهٔ noindex نمی‌شود.
- [ ] در production، نمایش به موتورهای جست‌وجو مسدود نیست؛ sitemap واقعی بازبینی و در Google Search Console ثبت/بررسی شده است (در صورت استفاده از Search Console).
- [ ] URL ناموجود در دامنهٔ واقعی status برابر 404 می‌گیرد، redirect ناموجه ندارد و صفحهٔ خطا به‌صورت soft 404 با status=200 تحویل نمی‌شود.
- [ ] structured data محصول ساده/متغیر با دادهٔ WooCommerce و محتوای قابل مشاهده تطبیق دارد؛ تعریف تکراری یا متناقض Product وجود ندارد.
- [ ] LocalBusiness schema فقط در صورت تأیید نام و نشانی واقعی و وجود کسب‌وکار/شعبهٔ مناسب تنظیم شده است؛ تلفن، ساعت، مختصات و محدودهٔ خدمت حدس زده نشده‌اند.
- [ ] Site Icon در تنظیم رسمی WordPress با فایل برند مصوب ثبت شده و تگ‌های icon در خروجی نهایی تکراری نیستند.
- [ ] `llms.txt` در صورت درخواست مالک و پس از تأیید دامنه/محتوا منتشر شده است؛ در غیر این صورت به‌عنوان مورد اختیاری و غیرتضمینی علامت «قابل اعمال نیست» خورده است.
- [ ] صفحات سیاست ارسال، مرجوعی، حریم خصوصی، شرایط فروش و راه تماس بازبینی و منتشر شده‌اند.
- [ ] نصب افزونه‌ها و آپدیت‌ها ابتدا در staging تست شده و پس از به‌روزرسانی امکان بازگشت به نسخهٔ پشتیبان وجود دارد.

## ۵. انتشار

- [ ] نسخهٔ production از commit بازبینی‌شدهٔ مخزن ساخته شده و فایل‌های هستهٔ WordPress، دیتابیس، آپلودهای کاربر و secretها در Git نیستند.
- [ ] درگاه ابتدا در حالت sandbox تست شده؛ تغییر به live فقط پس از تأیید حساب پذیرنده/ارائه‌دهنده و آزمون نهایی انجام می‌شود.
- [ ] در دسترس بودن سایت، گواهی TLS، تحویل ایمیل، تکمیل سفارش و بازیابی پشتیبان پس از انتشار دوباره بررسی شده‌اند.
- [ ] مالک فروشگاه مسئول پایش سفارش‌ها، بروزرسانی‌های امنیتی، درخواست‌های مشتریان، بازپرداخت و نگهداری داده‌ها مشخص است.

> **برای تکمیل انتشار واقعی لازم است:** دامنه، میزبان WordPress، اطلاعات فروشنده و کالاها، کشور/ارز، روش‌های ارسال و مالیات، ارائه‌دهندهٔ پرداخت و سیاست‌های تجاری واقعی مشخص و در حساب‌های مربوطه تنظیم شوند. این مخزن عمداً هیچ‌یک از این داده‌ها یا کلیدها را جعل نمی‌کند.

جزئیات فنی و منابع رسمی برای ۱۴ مورد SEO در [بازبینی SEO پیش از ادغام](seo-review-fa.md) ثبت شده‌اند. چک‌لیست بالا برای محیط زنده است؛ قبولی تست ایستای مخزن جایگزین آزمون staging نیست.
